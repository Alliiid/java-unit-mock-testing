Проект по разработке модульных (unit) тестов для классов доменной модели кошачьих (`Feline`, `Cat`, `Lion`) с применением изоляции зависимостей и достижением 100% покрытия кода по метрикам JaCoCo.

---

## 📌 Ключевые архитектурные решения

- **Инъекция зависимостей (Dependency Injection):** Устранена жесткая зависимость класса `Lion` от класса `Feline`. Экземпляр `Feline` передается через конструктор `Lion(String sex, Feline feline)`, что изолирует логику и упрощает тестирование.
- **Изоляция с Mockito:** Взаимодействие с внешними зависимостями изолировано через `@Mock` и стабы (`Mockito.when()`), что исключает влияние соседних модулей на результаты проверок.
- **Параметризация:** Проверки метода `doesHaveMane()` вынесены в отдельный класс с аннотацией `@RunWith(Parameterized.class)` для валидации всех допустимых вариантов пола.
- **100% Code Coverage:** Достигнуто полное покрытие строк и условий согласно отчету JaCoCo.

## 🧪 Покрытие тестами

### 1. `FelineTest`
* `getFamily()` — возвращает `"Кошачьи"`.
* `eatMeat()` — вызывает метод хищника `getFood("Хищник")`.
* `getKittens()` — возвращает 1 котенка по умолчанию.
* `getKittens(int kittensCount)` — возвращает переданное количество.

### 2. `CatTest`
* `getSound()` — возвращает звук `"Мяу"`.
* `getFood()` — проверяет корректный вызов метода получения еды через зависимость `Feline`.

### 3. `LionTest` (с использованием Mockito)
* Изолированная проверка вызовов `getKittens()` и `getFood()` через мок `Feline`.
* Проверка исключения `Exception` с текстом `"Используйте допустимые значения пола животного..."` при передаче некорректного пола.

### 4. `LionParamTest` (параметризованные проверки)
* Валидация метода `doesHaveMane()`:
  - `"Самец"` -> `true`
  - `"Самка"` -> `false`

### 5. `AlexTest` (дополнительное задание)
* Наследование от `Lion` с зафиксированным полом самец.
* Проверка методов `getFriends()` (Марти, Глория, Мелман) и `getPlaceOfLiving()` (Нью-Йоркский зоопарк).
* Проверка переопределенного `getKittens()` — возвращает 0.
